# ADR-008：有序列表投影与数量汇总

状态：已采用（本地候选）
日期：2026-10-20

GO2 待支付建单的实际 API 契约要求两个有序列表（订单行与运费商品）及 JSON 整数总数量。map 返回 flow 声明输出的对象列表，而 Decimal 返回金额字符串，不能靠隐式类型转换或虚构 API 完成这些映射。因此在 schema 0.3 中加入受限 `transform` 步骤，仅支持 project 与 positive_integer_sum，作为本次资产闭环的必要补齐。

source 必须是单一完整变量引用，path 是静态对象键/非负数组下标列表。project 对每项读取同一路径并保持顺序与 JSON 类型；缺字段即失败，不静默丢项。positive_integer_sum 要求非空来源且每项是 JSON 正整数，拒绝字符串、布尔、浮点、零及负数；总和保持整数并限制在 JSON 安全整数范围内。两种操作最多 1024 项，不提供通用表达式求值。

与 extract/decimal 一样，已知列表在首个请求前预检，动态列表在来源产生后、消费前验证；成功才发布 alias，trace.transforms 和 bindings 记录操作、路径、结果与来源。候选业务资产放在 Assets 独立 examples 目录，复用现有七个 API；正式工作区启用须在后续 Control/验证器/依赖交付完成后进行，避免正式锁定旧 Engine 时同步不可消费的场景。
