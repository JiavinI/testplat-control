# ADR-005：场景参数与公共流程

状态：已采用（分步实施）
日期：2026-10-19

## 决定与原因

用户已审核 scenarios 核心设计。case 为独立业务入口，flow 只供复用；独立运行需要 case 包装。业务场景集中展示和维护参数值，步骤及公共流程显式引用；“一个文件”描述使用体验，不限定物理存储。沿用 ADR-003 参数保存与顶层覆盖。common/private 是 case 内命名空间，不建立隐式覆盖或全局变量。

公共流程每次调用有独立 inputs 和局部 alias，只向父层发布声明 outputs；禁止直接读取根 case 参数或其他调用内部状态。新契约版本保持原 Case 0.2 的严格规则及历史形状。嵌套调用从第一切片提供调用 ID、父子关系、输入输出与引用来源，不在 Control 重写 DSL。

## 第一切片边界

新增场景 schema 0.3：API 和 flow 步骤沿用 params 作为调用绑定，flow_id 引用公共流程；flow 声明类型化必填 inputs 及 outputs 表达式。API alias 保持安全响应结构，flow alias 仅含声明输出。新结果 result_version=0.3，步骤增加 trace（子步骤位于 trace.children）；旧结果不新增字段。Engine 公共 describe_case 统一读取定义并验证引用，运行时再完成配置与动态值校验。

暂不增加 map、任意表达式、金额计算、UI 和跨平台执行。平台目标、精确提取和完整业务验收按后续切片落实。切片 1 用当前 case.params 存储集中默认值，避免为 UI 需求增加不必要的数据文件机制。

## 备选与影响

未采用 flow 隐式读取 case 全局参数、共享局部变量或内置业务默认值，避免复用时相互污染。未改造旧 schema 容忍新增字段，避免旧兼容规则漂移。Control 通过 Engine 公开描述入口读取新版定义，不另建 YAML 执行语义。

产品设计与验收见 [核心设计](../requirements/scenarios-core-design.md)。正式远程依赖交付仍须先交付 Engine，再精确锁定 Control；本地验证不等同远程可交付。

## 后续扩展：有序 map

2026-10-20 增补：为表达按商品列表重复解析等业务编排，schema 0.3 增加受限 `map` 步骤。map 必须引用一个 flow，并将单一数组 source 和完整的 flow.inputs 绑定写在调用点；每项依序串行执行，局部暴露 `item` 与从 0 开始的 `index`，只聚合 flow 声明 outputs。非数组或空数组在首个请求前拒绝；任一项失败即停止并记录剩余项 skipped。map 不支持隐式 case 读取、并发、表达式或自动重试。此能力复用原 flow/trace/身份边界，不改变旧 Case 0.2；提取、精确匹配、Decimal 与断言仍是后续切片。
