# ADR-002：平台、项目与配置归属

状态：已采用
日期：2026-10-18

后续参数与公共配置归属见 [ADR-003](ADR-003-参数归属与公共配置.md)，不改变本文的平台、项目和配置共享关系。

## 决定

功能内使用平台＋业务项目两级选择。保留现有 Project ID 作为运行工作区标识，避免重命名 main/gsb 和迁移执行历史。通过资产清单 workspace 元数据及新增绑定表，明确记录平台、业务项目和配置所属工作区。

GO2 网站与 GO2 的 GSB 共享已有 main/gsb 的环境和身份；E3E3 网站与其 GSB 共享独立配置。独立后台的多个业务项目上下文共用各自后台配置，不复制网站身份。配置服务和运行解析使用同一归属规则；执行记录和登录缓存仍按实际运行工作区隔离。共享配置只能直接引用同仓工作区，且 config 路径必须相同，禁止归属链。

## 原因与影响

直接重命名 Project 或复制现有凭据会影响历史、路由和后续修改的一致性。仅改标签无法可靠表达平台关系。新增绑定保留旧清单、旧路由和数据兼容；界面明确告知共享配置的影响。

网站身份共用不代表 API token 等于网站 Cookie。初始网站资产只提供匿名 SSO 入口检查；未适配的代发后台验证码登录显式标记不可执行，保留独立凭据字段，不伪造协议。复杂登录适配与真实登录验收另行推进。
